# Pack DOS version matrix (CONFIG.SYS / AUTOEXEC.BAT)

Pack boot files are generated by **`packcli.boot_rules`**, not hand-copied from
`boot-c.zip` alone. dosforge still **installs** the OS (`--boot-mode`); packcli
writes the final **CONFIG.SYS** and **AUTOEXEC.BAT** for that mode.

## Recipe / skill selection

```yaml
options:
  dos: auto          # or any dosforge boot-mode name
  # aliases: boot: …  (same field)
  audio: sb | gus
  target: mister | picomem | picogus | picoide
```

Env/config: `MISTER_PACK_DOS` / `MISTER_PACK_BOOT` / `config.toml` `dos` or `boot`.

| Value | Meaning |
|-------|---------|
| **auto** | ≤ ~1.9 GiB → **msdos622** + FAT16; larger → **msdos71** + FAT32 |
| **msdos622** | Default explicit choice (FAT16) |
| **msdos71** / **pcdos71** / **freedos** | FAT32-capable |
| Other dosforge modes | Full catalog (see below) |

## Conventional memory policy

For every mode, packcli prefers the path that leaves the **most free base RAM**:

1. **Native UMB** (MS-DOS 5+/6+/7+, FreeDOS): `HIMEM` → `EMM386`/`JEMM386` → `DOS=HIGH,UMB` → **`DEVICEHIGH` / `LOADHIGH`** for CD, SETVER, mouse, SHSUCDX, DOSLFNM.
2. **No native UMB** (DOS 3.x, DR-DOS pack profile, etc.): stage **QEMM** and use **LOADHI** when `include_qemm: true`.
3. **No high memory at all**: load drivers low (last resort).

## MS-DOS 6.22 default shape

- **CONFIG.SYS**: multi-config menu; default **EMM386** (HIMEM + `EMM386.EXE AUTO RAM` + `DOS=HIGH,UMB` + DEVICEHIGH XCDROM/SETVER). Profiles: EXTENDED, CLEAN, QEMM.
- **AUTOEXEC.BAT**: audio block (packcli sb|gus) → env → `GOTO %CONFIG%` → COMMON: LOADHIGH SHSUCDX/mouse/DOSLFNM → **MyMenu once** → `GOTO END` (no remenu loop).

## Implementation

- Capabilities: `packcli/boot_rules/capabilities.py`
- Renderer: `packcli/boot_rules/render.py`
- VHD write path: `dosforgevhd._writeRootBootFiles` after boot-mode resolve
